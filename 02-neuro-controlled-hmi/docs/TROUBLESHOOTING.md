# Project 02 — Troubleshooting

> **Conditional research matrix, not verified remedies.** The lab band model is unknown. Record exact model, official app/SDK version, host OS, timestamp, and non-sensitive error text before diagnosis. Use only manufacturer instructions for a physically matching unit. Do not buy/install missing items, bypass authentication, alter firmware, or publish serials, credentials, Developer Codes, raw biometric data, or personal identifiers.

| Problem | Possible cause | Verification | Safe response |
|---|---|---|---|
| Physical band cannot be identified | Generic inventory label, missing model marking/package, mixed devices | Read manufacturer and model from the physical device/package; compare with matching official manual | Do not apply SB-02 specifications; record identity blocker and continue to next project |
| Candidate SenzeBand app/SDK does not recognize the band | It may not be a Neeuro product/SB-02; wrong vendor app; unsupported revision | Compare exact physical model and SDK-supported model list | Stop; do not scan undocumented BLE characteristics or try another device profile |
| Host cannot see/pair with a confirmed SB-02 | Host OS/Bluetooth limitation, device not charged, another connection, range/interference, app mismatch | Follow exact vendor pairing/discovery steps and status UI; record host/SDK versions | Use only included/available accessories and supported steps; if host or adapter is missing, mark blocked, do not buy |
| SDK authentication fails | Missing/invalid Developer Code, license/access issue, Internet permission, vendor service unavailable | Check the existing authorized account/package and exact SDK error; do not disclose credentials in logs | Do not bypass authentication or request/procure access; mark integration blocked if authorization is not already provided |
| Signal/contact status is poor | Incorrect fit, damaged/dirty electrodes, motion, model mismatch | Follow exact vendor fit/cleaning procedure and inspect only as permitted by its manual | Stop collection if discomfort/damage; do not disable signal-quality checks or add gel/parts unless the exact manual and supplied kit provide them |
| Samples are missing or stale | BLE loss, app not active, callback cadence misunderstanding, SDK buffering | Compare API timestamps/status with documentation for the exact SDK package | Suppress/clear requests; reconnect only through documented steps; report dropout rather than interpolating silently |
| Mental-state output fluctuates | Signal artifact, calibration drift, short dwell, vendor processing variability | Compare quality flags and per-session baseline; inspect timestamps and condition | Keep requests disabled or require human confirmation; recalibrate only with approved protocol; do not claim intent or force a classifier |
| Requests appear during no-request intervals | Threshold too permissive, drift, artifact, stale data not gated | Review event markers, false requests, freshness and quality flags | Increase no-action gating only as a measured change; remain display-only; stop if acceptance criteria fail |
| HMI is slow | API callback cadence, vendor authentication/connection delay, dwell/cooldown, host load | Measure event-to-display timestamps by stage | Report p50/p95; do not remove quality/safety gates merely to reduce latency |
| App build fails | SDK/runtime unavailable or unsupported, access/package missing | Record first diagnostic and versions from already-provided software | Do not install/purchase an unprovided SDK/runtime; record the blocker and continue |
| RSLK does not receive a request | Not part of P02 MVP; P01 identity/link and integration unverified | Check project status and confirm no robot link should be active | Keep robot unconnected; no pin/serial/BLE protocol can be inferred from this project |

Add a “verified remedy” only after reproducing it with the exact physical model and supported software version.
