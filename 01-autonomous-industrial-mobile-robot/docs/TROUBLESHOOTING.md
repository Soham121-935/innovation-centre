# Project 01 — Troubleshooting

> These are diagnostic starting points, not verified outcomes on the lab units. Use the exact board guide, disconnect power before changing wiring, and stop if the physical hardware does not match the selected profile.

| Problem | Possible cause | Verification | Solution |
|---|---|---|---|
| RSLK version cannot be identified | Generic inventory label; missing box/manual; mixed parts | Read kit label, chassis silkscreen/revision, LaunchPad marking, sensor part labels; compare to [VERIFICATION.md](../hardware/VERIFICATION.md) | Do not power or use the MAX pin map. Photograph/record the parts and research the exact board. |
| LaunchPad not detected by PC | Charge-only USB cable, USB port/driver, damaged connector, board not receiving power | Try a known data cable/port; inspect OS device manager and XDS/debug LEDs using the exact LaunchPad guide | Install the documented driver/device support; replace only a verified faulty cable. Stop if hardware heats or is damaged. |
| CCS cannot connect/program | Wrong target/MCU, unsupported CCS/device support, debug probe or board revision mismatch | Confirm MCU marking, LaunchPad revision, target config, probe selection, device-support/SDK versions | Re-select the documented MSP-EXP432P401R target only if it matches. Preserve the complete error log; do not use a different target as a workaround. |
| Program builds but no LED/serial output | Wrong example, firmware not running, wrong backchannel/port/settings, LED pin differs by revision | Verify the exact TI example and LaunchPad guide; confirm the debug session reached the running state | Restore the board-only example, check the documented onboard LED/USB backchannel, and record terminal settings. No motor code yet. |
| Chassis will not power or unexpectedly resets | Battery set/polarity, switch/latching sequence, jumper/power configuration, damaged rail, bad connection | Power off; inspect battery type/count/polarity and exact board guide. Measure only documented rails with a meter and supervisor approval. | Correct the verified power configuration. For a confirmed MAX, inspect the LaunchPad +5 V jumper warning in TI SEKP164. Do not repeatedly cycle a suspect board. |
| LaunchPad/chassis becomes hot, smells, or smokes | Short, reversed/mismatched power, +5 V jumper left installed, misaligned headers, overloaded rail | Disconnect all power immediately; visually inspect without re-energizing | Do not retest. Notify the lab supervisor and use the official repair/inspection procedure. |
| Motor does not turn or stalls | Motor/connector issue, wrong profile, driver asleep, low battery, excessive load, mechanical jam | Wheels raised; verify exact MAX direction/PWM/sleep map and motor connector; inspect wheel by hand with power off | Remove obstruction and follow the verified driver sequence. Never hold the motor stalled against an object. Stop if the encoder is absent or hardware heats. |
| Motor turns opposite direction | Left/right orientation or direction polarity differs from assumptions | Wheels raised, very low safe test command, compare to the verified MAX map | Correct only the named board profile after confirming physical orientation. Do not swap wires/logic arbitrarily. |
| Encoder is always zero or noisy | Missing encoder assembly/connection, wrong pin map, capture setup, loose connector, false edges | Turn one wheel by hand on a raised chassis; inspect each channel in a logic analyzer/debugger using the verified map | Reseat only with power off; verify input mux/capture config and channel sequence; calibrate the actual count convention. |
| Reflectance sensor has identical values on all surfaces | Sensor not powered/illuminated, height/orientation, wrong board, incorrect timing, unsuitable floor contrast | Test each channel over known light/dark surfaces; verify the sensor board and illumination pins against its guide | Correct mounting/timing for the verified sensor; change marker material/geometry only after raw data are captured. |
| Range sensor gives saturated, inverted, or erratic values | Wrong sensor model, supply or ground issue, sensor blind zone/nonlinear curve, missing filter/decoupling, ADC scaling, target material | Read part label/datasheet; check documented supply, output range, filter path, and known-distance response without driving | Power off; reconnect only per exact sensor/chassis documentation; recalibrate a lookup/threshold table. Never apply the sensor's 5 V supply to an MCU input. |
| Obstacle is missed or causes a bumper hit | Sensor blind zone/coverage, too high speed, stale sampling, bad threshold, sensor set absent | Review raw timestamps/distance values, target placement, mounting and measured stopping distance | Reduce speed, expand validated coverage if justified, and set threshold using measured latency/braking distance. Do not disable bump/physical stop. |
| False stops on open floor | Surface/ambient response, thresholds too tight, single-sample decision, stale calibration | Inspect raw range/reflectance logs and verify test target/surface | Add validated persistence/hysteresis and sensor-validity checks; recalibrate on the actual course. |
| Robot drifts from route | Wheel mismatch/slip, encoder scale, wheelbase calibration, missed floor marker | Compare straight/square runs with measured floor marks; inspect encoder/marker logs | Calibrate each unit, reduce speed, add/space landmarks appropriately, and report residual drift. Do not call it absolute localization. |
| Mission does not re-route | No alternate graph path, edge map not updated, planner/state bug | Print the configured graph, blocked-edge event, and route-search result | Correct the map or planner; if no path is available the correct behavior is safe stop and explicit blocked event. |
| Build/test results differ between runs | Battery state, wheel/floor variation, unrecorded firmware/config, sensor timing | Compare trial metadata and raw logs; repeat with controlled variables | Freeze configuration/calibration and report variation/failures; do not publish only the best run. |

For new faults, add the hardware ID/revision, safe reproduction steps, original logs, root cause, and a reproduced fix. Do not guess pin numbers.
